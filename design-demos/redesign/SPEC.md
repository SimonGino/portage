# Portage 管理端整站重构 · 原型 spec

这是一次性视觉/信息架构原型的共同输入。三套逻辑只换骨架和气质，**内容、术语、页面职责必须一致**。不改 `web/` 生产代码，不回写口径。

## 产品是什么

Portage = 个人自用 AI 网关的管理端。每天做的事：纳管模型、签发客户端钥匙、追查一次调用、给模型起对外名、看谁在烧 token。不是聊天产品，不是官网。

标记 path（必须原样画进页眉，`currentColor`）：

`M3,6 L21,6 L17,13 L7,13 Z M0,17 L9,17 L9,21 L0,21 Z M15,17 L24,17 L24,21 L15,21 Z`

## 本次 IA（已按 PO 口令，渠道不再占顶栏）

导航五项，顺序即优先级，默认落地「模型」：

1. **模型** — 主语是纳管模型列表。渠道变成「从哪家上游来」的分组/左栏，不再是首页。主动作：获取模型列表、纳管、启停、复制限定名 `渠道名/模型名`、协议子集。渠道的 base_url / 凭证池 / 探测收到本页的「这家上游」面板（抽屉或右栏次级），必须能从模型页到达，不能丢。
2. **API Key** — 主语是客户端钥匙。主动作：新建、显示/复制、模型白名单、启停。跟上游凭证是两回事，文案必须写清。
3. **调用记录** — 主语是刚才那几次。主动作：只看失败、按模型筛、点开详情（request-id 可复制；上游原文只在失败行）。
4. **接入点** — 主语是对外别名。主动作：新建、绑一个候选（渠道+纳管模型）。说明：只想直连用限定名即可，不必建。
5. **排行** — 主语是谁在烧。名次 + 名字 + token + 占比。维度：按模型 / 按 API Key / 按上游凭证。窗口：1 / 7 / 30 天。只留一个合计（占比分母）。不要热门榜、不要厂商市场份额、不要环比涨跌。

**去掉概览。** 改密码 / 退出收到账号角落。

每页必须一眼能读出动词（「能干嘛」），用超大标题或超大主按钮，不要用栏目名冒充。

建议页标题（可改写但必须是动词/问题，不是栏目）：

- 模型：纳管这些模型
- API Key：签发一把钥匙
- 调用记录：刚才那几次怎么样
- 接入点：给模型起个对外的名字
- 排行：谁在烧

## 硬约束（气质再疯也不能破）

- 术语：渠道 / 纳管模型 / 接入点 / 候选 / 凭证池 / 上游凭证 / API Key。禁止「供应商」「网关 key」「用量」当页名。
- 不展示完整上游 key 或 base_url 在列表里；凭证默认掩码，给「显示」。
- 不做计费、配额、多用户、厂商市场份额、环比。
- 颜色可以疯，但成功 / 警告 / 失败必须还能靠文字认出来，不能只靠色。
- 中文界面。`text-wrap: pretty`。正文 ≥14px，对比度 ≥4.5:1。
- 反 slop：禁止紫渐变万能公式、禁止 emoji 当图标、禁止每块卡左边一条彩色 accent、禁止 Inter 当 display、禁止 `#0D1117` + 青紫霓虹。
- 单文件 HTML，`file://` 能开。Google Fonts 可 CDN。五页在同一文件里用按钮切换（不要真路由）。
- 可点：五项导航、模型页切换渠道、打开「这家上游」面板、打开调用详情、切换排行维度。不必真的增删数据。
- 布局骨架必须跟另外两版不同（本 agent 只做自己那一版，不要猜另外两版长什么样——按下面给你的那一版骨架做）。
