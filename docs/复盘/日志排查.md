日志走 stderr（slog 文本格式，Info 级），三个标记都是 Warn 行，直接 grep 就行。

看日志的命令（compose 部署，服务名 portage）：

# 实时盯
docker compose -f deploy/docker-compose.forward.yml logs -f portage | grep -E 'orphan_result|missing_result|残缺的工具入参'

# 回看历史
docker compose -f deploy/docker-compose.forward.yml logs --since 24h portage | grep -E 'orphan_result|missing_result|残缺的工具入参'

裸二进制部署就把 stderr 重定向到文件再 grep 同样的模式。

三条各长什么样（internal/server/convert.go:106-123）：

- 两个档位在同一条 Warn 里：msg="跨协议转换丢弃字段" inbound=... channel_protocol=... dropped="[orphan_result[id1,id2] missing_result[id3]]"。方括号里是 call id 名单。
- 入参救治单独一条：msg="回带历史里有残缺的工具入参，已替换成 {}，..." channel=... calls="[...]"。只在入口是 Responses 协议时才会出现。

判断真机样本：命中任一条就是。再用同一行的 channel / inbound / channel_protocol 定位是哪条链路，配合 call id 到管理端调用记录里对回原始请求体，就能拿去当 golden 样本。

一个注意点：日志级别固定 Info，Warn 一定会打，不用改配置。但 compose 默认 json-file driver 没配轮转，--since 拉太长会慢，建议加 --since。
